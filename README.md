# Explorables

A small, hand-built library of interactive explanations. Each concept is a live
model the reader manipulates with parameters — not a video, not a static diagram.

Built to `SPEC.md`. **Current state: M5 — all five milestones complete.**

## Running it

```
npm install
npm run dev          # dev server
npm run build        # production build
npm test             # unit tests (Vitest)
npm run test:e2e     # smoke tests (Playwright)
npm run lint:types   # tsc project build

npm run build:fonts  # re-download the three woff2 subsets (rarely needed)
npm run build:og     # regenerate the static Open Graph cards
```

Set `SITE_ORIGIN` when building for deployment. Without it the pages still build
correctly, but canonical URLs, absolute OG image URLs, `sitemap.xml` and
`robots.txt` are skipped — a guessed domain in a canonical tag is worse than
none.

```
SITE_ORIGIN=https://your-domain npm run build
```

Analytics are off unless configured. Set `VITE_ANALYTICS_SRC` and
`VITE_ANALYTICS_DOMAIN` (Plausible or Umami) to enable cookieless page views
plus the single `parameter_changed` event.

## What exists

**The engine**, in `src/engine/` — the parameter schema (`params.ts`), the state
hook with URL sync (`useParams.ts`), the generated control panel
(`Controls.tsx`), the shared SVG plot primitive (`Plot.tsx`), the DPR-aware
canvas wrapper (`Canvas.tsx`), token reading for canvas drawing (`tokens.ts`),
analytics (`analytics.ts`), and supporting hooks.

`src/lib/stats.ts` holds pure numerics shared across the statistics explorables
— a seeded generator, the normal distribution, and least squares. It is a
deliberate addition to the §3.2 layout, explained in that file's header.

**Nine explorables**, each complete to the §12 definition of done: a pure model
with tests against analytical results, all five prose sections, at most six
parameters, URL round-tripping, a 375px layout, and an `aria-live` description.

| Slug | Domain | What it is about |
|---|---|---|
| `wave-interference` | Physics | Two sources, and why adding waves can give nothing |
| `tax-incidence` | Economics | Who really pays a tax, and why the law does not decide |
| `survival-analysis` | Statistics | Censoring, and why discarding unfinished rows is not neutral |
| `bayes-base-rates` | Statistics | Why a very good test for a rare thing is mostly false alarms |
| `central-limit` | Statistics | How fast averages become normal, and when they have not |
| `statistical-power` | Statistics | Power, and the exaggeration an underpowered win carries |
| `simpsons-paradox` | Statistics | Aggregation reversing the sign of an effect |
| `bias-variance` | Statistics | Overfitting, and the decomposition of test error |
| `gradient-descent` | Statistics | Step size, conditioning, and momentum |

**The site around them** — an index at `/` generated from the registry, real
pre-rendered HTML for every route with the prose in the markup, per-route
titles, descriptions, canonical URLs, Open Graph tags and JSON-LD, a sitemap,
static OG cards, and the three typefaces self-hosted.

## Notes on the build

- **Fonts.** All three faces of §2.2 are self-hosted as latin woff2 subsets in
  `public/fonts`, generated by `scripts/build-fonts.mjs` and committed. Nothing
  is fetched from Google at runtime, which §10 forbids; the CDN is used once at
  build time as a source of files. `font-display: swap` means the system
  fallbacks in `tokens.css` still matter for the first few hundred milliseconds.

- **Pre-rendering.** `src/prerender/entry.ts` is the "simple build-time HTML
  shell generator" §10 offers as the alternative to `vite-plugin-ssr`, so no
  dependency was added. It writes each route in two shapes — `slug.html` and
  `slug/index.html` — because static hosts disagree about which one serves an
  extensionless `/slug`; the canonical tag names one of them. The prose in the
  shell is semantic HTML rather than a copy of the styled component, since
  CSS-module class names are hashed at build time.
- **Bundle.** Initial JS is ~82KB gzipped against the §9 budget of 150KB. Two
  things keep it there. KaTeX (~77KB gzipped on its own) is loaded on demand by
  `Equation.tsx` rather than shipped in the initial chunk. And each explorable's
  View and model are route-level code-split, per §9: `meta` and `schema` stay
  eager because the registry needs them to route and to pre-render, while the
  drawing code arrives only when that explorable is opened.
- **Determinism.** §0 forbids nondeterminism, so every "sample" comes from a
  seeded generator keyed on the parameters. The same URL always produces the
  same dataset, and model tests can assert exact numbers.
- **Dependencies.** Only what §3.1 names. D3 is imported as `d3-scale` and
  `d3-shape` submodules, never the bundle, and is used as a maths library —
  React owns the DOM. No router was added for slug-based routing (§13: ask
  first).
